# 자소서 작성/재작성 스킬

이 볼트는 회사별 자소서를 `content/Job_Hunting/2026하반기/자소서들/{회사명} 자소서.md`에 저장하고,
재사용 가능한 경험은 별도 포트폴리오 문서에서 관리한다. 매번 새로 쓰지 말고 아래 순서를 따른다.

## 0. 항상 먼저 읽는 세 문서

1. `content/Job_Hunting/자소서_가이드라인.md` — 톤앤매너·구조·직무연관성·디테일 깊이 규칙. 모든 문장이 이 규칙을 통과해야 한다.
2. `content/Job_Hunting/내 포트폴리오 아이템 정리.md` — 재사용 가능한 경험/연구/프로젝트 단위 정리. 문항에 쓸 소재는 여기서 고른다. 특히 각 아이템의:
   - "본인 기여 범위" (팀 성과를 단독 성과처럼 과장하지 않기)
   - "진행중 vs 완료" 구분 (완료된 논문 성과와 현재진행중 후속 연구를 섞어 인과관계를 조작하지 않기)
   - "NDA/공개 수위" 주의사항
   을 반드시 확인하고 위반하지 않는다.
3. `content/Job_Hunting/2026하반기/logs/{회사명}.md` — 해당 회사 JD 원문, 서류/코테 일정. JD의 "수행업무"·"필요역량"·"우대사항"을 스펙 시트로 취급해 커버리지 표를 머릿속으로(또는 실제로) 만든다.

기존 자소서 파일이 이미 있으면 그것도 읽어서, 어떤 문항이 이미 검증된 소재(과거 서류 합격 이력)를 쓰고 있는지 파악한다. 검증된 소재는 함부로 갈아엎지 말고, 사용자가 명시적으로 "이건 바꾸고 싶다"고 한 문항만 재구성한다.

## 1. 문항별 소재 배정

- 문항 텍스트를 절 단위로 쪼개 요구사항 체크리스트를 만든다 (가이드라인 2-①).
- JD 키워드(예: "합성 데이터 생성", "모델 경량화", "Agentic AI", "LLM-as-a-Judge")를 포트폴리오 아이템과 매칭한다. 라벨 대 라벨 매칭이 아니라 "문제의 구조"로 연결한다 (가이드라인 3-③).
- 같은 경험을 문항마다 다르게 쓰는 건 괜찮지만, 이미 이 문서의 다른 문항이나 이 회사의 CV형 항목에서 쓴 경험은 가급적 피하거나 각도를 바꾼다(가이드라인 2-⑤). 사용할 수 있는 소재가 마땅치 않으면 사용자에게 방향을 제안하고 실제 경험을 물어본다 — 지어내지 않는다.
- 진행중인 연구를 쓸 때는 완료된 성과(논문 게재 등)와 진행중 작업(아직 미게재)을 한 문장 안에서도 명확히 분리해서 서술한다. "그 결과 게재되었다"처럼 진행중 작업을 완료 성과로 귀속시키는 인과 오류를 만들지 않는다.

## 2. 문장 작성 규칙 (가이드라인 요약, 반드시 적용)

- 격식체 통일: "-습니다"체로 통일, 구어·축약("나눠"→"나누어", "겪어봤"→"겪어보았") 제거.
- 강한 동사, 완화 표현 금지: "~하려고 노력했습니다" 대신 "~했습니다".
- 확신의 크기 = 증거의 크기: 프로젝트 1건을 분야 전체로 확장하지 않기.
- 인용 부호는 큰따옴표(`"..."`)만 사용. 작은따옴표(`'...'`) 금지.
- 나열은 가운뎃점(·)이 아니라 쉼표(,)로. 단, 문항 원문(회사가 낸 질문 텍스트)은 그대로 두고 건드리지 않는다.
- 같은 개념을 다른 단어로 재등장시키지 않기 (예: "파고들면"과 "원리부터 파고들어"를 한 문단에 같이 쓰지 않기).
- 인간적으로 읽히게: 지나치게 기계적인 병렬 나열, 반복되는 종결 패턴을 피하고 문장 리듬을 섞는다. 단, 사실관계·수치·고유명사는 절대 바꾸지 않는다.

## 3. 글자수 검증 (필수, 매번 실행)

각 문항 아래 답변은 md 파일에서 한 줄(하나의 문단)로 작성되어 있다. 수정 후 반드시 PowerShell로 실측한다 — 눈대중으로 통과시키지 않는다:

```powershell
$path = "content/Job_Hunting/2026하반기/자소서들/{회사명} 자소서.md"
$lines = Get-Content -Path $path -Encoding UTF8
$lines[$n-1].Length   # $n은 1-indexed 줄 번호
```

문항 제목 옆에 적힌 글자수 제한(예: "(600자)")을 넘기면 반드시 줄인다. 5번처럼 여러 경험을 나눠 쓰는 문항은 경험별 권장 글자수(보통 총 글자수/경험 개수)도 참고하되, 총합만 제한을 넘지 않으면 된다.

## 4. 마무리 체크리스트 (가이드라인 5절 그대로 적용)

1. 질문의 각 절이 답변됐는가
2. JD 커버리지 갭이 있으면 최소 비용으로 메웠는가
3. 문장 삭제 테스트 + 재등장 단어 확인
4. 자소서 문장 ↔ 포트폴리오 문서의 실제 사실 대조 (특히 진행중/완료, 저자 순서, 특허 발명자 순번, 기여 범위)
5. 표기 통일 (회사명, 전문용어, 인용부호, 나열 기호)
6. 구어·축약·완화 표현 제거
7. 글자수 실측 확인

## 5. 새로 나온 소재는 포트폴리오 문서에 역으로 반영

작업 중 사용자가 포트폴리오 문서에 없던 새 경험(예: 특정 AI 툴을 활용한 사례)을 알려주면, 자소서에 쓰는 데서 끝내지 말고 `내 포트폴리오 아이템 정리.md`에도 아이템으로 추가할지 사용자에게 물어본다. 이 문서가 계속 자라야 다음 회사 자소서 작성이 더 빨라진다.
