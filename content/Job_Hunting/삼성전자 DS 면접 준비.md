## 2. 1분 자기소개

### 구조 틀

> **인적사항 소개 → 지원동기 → 합격을 위한 노력 (전공·대외활동·프로젝트) + 강점 → 목표 (Short-term / Long-term) → 마무리**

### 작성 주의사항

- ❌ "메타버스·AI의 발달로 반도체가 중요합니다" 같은 **누구나 아는 클리셰 금지**
- ✅ **구체적인 수치**로 말할 것 (ex. 성능 XX% 향상, 본선 진출 등)
- ✅ 지원 직무는 **사업부 → 제품 → 공정** 수준까지 언급해 관심도를 보일 것

### 예시 답변 (DS AI센터 SW개발)

안녕하세요, DS AI센터 SW개발 직무에 지원한 [이름]입니다. 저는 **수학적 구조를 이용해 AI가 기존에 풀지 못했던 문제를 푸는 것**에 집중해온 연구자입니다.

석사 과정 중 '왜 AI는 숫자 계산을 잘 못하는가'라는 질문을 파고들었습니다. 기존 토크나이저는 숫자를 문자처럼 쪼개기 때문에 덧셈도 곱셈도 의미 있게 표현하지 못합니다. 저는 대수학의 Adele Ring 구조를 이용해 학습 없이도 숫자의 대수적 관계를 보존하는 임베딩 방법을 직접 설계했습니다. 고난도 수학 벤치마크에서 기존 대비 약 39% 성능이 향상됐고, 이 연구는 NeurIPS Workshop에 게재되었습니다.

연구 외에도 삼성이 주최한 SCPC AI 챌린지에서 3B 파라미터 제약 안에 고난이도 추론이 가능한 온디바이스 VLM을 직접 구현해 본선에 진출한 경험이 있습니다.

반도체 공정은 AI에게 가장 가혹한 도메인입니다. 나노 단위의 수치 하나가 수율을 결정하는데, 기존 AI는 그 숫자조차 제대로 파악하지 못합니다. 저는 바로 그 문제를 풀어내보고자 연구해온 사람입니다. 감사합니다.

**Q. 상사의 부당하거나 불법한 지시를 받는다면?**

불법적인 지시라면 명확히 거절하겠습니다. 부당하다고 느끼는 지시는 먼저 지시의 배경과 의도를 충분히 이해한 뒤, 제 의견을 논리적으로 전달하겠습니다. 최종적으로 조직의 결정을 따르되, 윤리적 판단은 타협하지 않겠습니다.

**Q. 팀 활동에서 힘든 일이 생기면?**

갈등은 따로 만나 밥이나 커피를 하며 진솔하게 터놓고 이야기하는 편입니다. 서로의 입장 차이를 먼저 이해하고, 공통의 목표를 중심으로 합의점을 찾아갑니다.

**Q. 야근·높은 업무 강도에 대한 각오는?**

업무의 성취감이 크기 때문에 강도 높은 환경도 긍정적으로 받아들일 수 있습니다. 스트레스 관리 방법도 갖추고 있어 지속적으로 좋은 퍼포먼스를 낼 수 있습니다.

**Q. 이 면접에서 떨어진다면?**

매우 아쉽겠지만, 바로 다른 대안을 찾기보다 제가 어떤 직무 역량이나 기업 이해도가 부족했는지 객관적으로 분석하겠습니다. 개인 프로젝트와 실무 경험으로 보완한 뒤, 다음 채용에 반드시 재도전하겠습니다.

**Q. 다른 회사에도 지원했나요?**

**Q. AI 모델 개발과 AI 시스템 개발의 차이는?**

 AI 모델 개발이 반도체 공정의 난제를 해결하기 위한 '지능(Brain)'을 설계하는 과정이라면, AI 시스템 개발은 

**Q. 반도체 산업에서 AI가 가장 큰 가치를 만드는 지점은?**

인간의 인지적 한계를 넘어선 **수율 극대화**와 **공정의 완전 자율화(Dark Factory)** 에 있습니다. AI가 수만 대 설비의 센서 데이터를 실시간 분석해 불량 패턴을 사전에 예측하고, 나아가 스스로 이상을 감지하고 조치하는 자율형 공장을 실현하는 것이 궁극의 가치입니다.

**Q. 반도체 공정에서 AI 활용 사례를 아는가? (Yield prediction, OPC, APC 등)**

세 가지 대표 사례를 잘 알고 있습니다.
 - **수율 예측(Yield Prediction)**: 설비 센서 데이터를 실시간 분석해 최종 양산 결과의 불량 가능성을 사전에 파악
- **OPC(Optical Proximity Correction)**: 나노 단위 미세 패턴 설계 시 발생하는 왜곡을 AI 시뮬레이션으로 보정해 노광 공정 정확도 향상
- **APC(Advanced Process Control)**: 수백 개 공정 스텝 사이에서 설비 파라미터를 실시간 미세 조정해 공정 산포 최소화

**Q. FAB이란?**

FAB(Fabrication Plant)은 실리콘 웨이퍼를 가공해 반도체 칩을 대량 생산하는 제조 공장입니다. 미세 파티클 하나에도 수율이 치명적인 영향을 받으므로 내부는 '클린룸(Clean Room)'으로 유지되며, 수백 번의 정밀 공정이 이뤄지는 고도 자동화 시설입니다.

**Q. 다크 팩토리(Dark Factory)란?**

생산 공정 전반이 완전 자동화되어 사람의 개입 없이 24시간 자율 가동되는 무인 공장입니다. 조명·냉난방 같은 인간 중심 설비가 불필요하고, 로봇·센서·AI가 시스템 전체를 통제하며 생산을 최적화합니다.

### 5-2. AI·ML 기술 질문

**Q. 딥러닝과 머신러닝의 차이는? 각각 언제 적합한가?**

머신러닝은 사람이 특징(Feature)을 직접 설계해 모델에 입력하는 방식이고, 딥러닝은 신경망이 데이터로부터 특징을 스스로 학습합니다. 데이터가 적거나 해석 가능성이 중요한 상황에서는 머신러닝이 적합하고, 이미지·언어처럼 고차원 비정형 데이터에는 딥러닝이 강점을 발휘합니다.

**Q. 대규모 데이터에서 의미 있는 패턴을 찾을 때 접근 방식은?**

먼저 데이터의 분포와 품질을 탐색(EDA)하고, 도메인 지식을 바탕으로 유의미한 특징을 선별합니다. 이후 비지도 학습(클러스터링, 차원 축소)으로 구조를 파악한 뒤, 지도 학습 모델로 검증하는 순서로 접근합니다.

**Q. 모델 성능과 시스템 효율이 충돌할 때 어떻게 판단하는가?**

현장의 필수 제약 조건을 최우선 기준으로 삼겠습니다. 반도체 FAB처럼 24시간 실시간 제어가 생명인 환경에서는 지연 시간과 처리량이 단순 정확도보다 우선되는 경우가 많습니다. 아무리 완벽한 판단도 제어의 골든타임을 놓치면 막대한 손실이 생기기 때문입니다. 단, 단순 타협이 아닌 양자화·경량화 등 구조적 엔지니어링으로 두 요소의 최적점을 찾겠습니다.

**Q. 데이터 품질이 좋은데 실제 시스템 성능이 낮다면?**

모델 외부 요인인 **데이터 드리프트**와 **서빙 파이프라인의 병목**을 먼저 의심하겠습니다. 학습 데이터와 실시간 유입 데이터 간의 분포 차이(Data Drift)를 확인하고, 직렬화 오버헤드나 하드웨어 가속기 활용 최적화 미흡 여부를 분석하겠습니다.

**Q. NPU 타겟 최적화와 일반 GPU 최적화의 차이는?**

GPU 최적화가 강력한 하드웨어를 바탕으로 FP16/FP32 정밀도의 처리량을 높이는 과정이라면, NPU 최적화는 전력·메모리 제한 환경에서 INT8 이하로 양자화하고, 하드웨어 아키텍처에 종속적인 타일링·연산자 통합 같은 컴파일러 레벨 최적화가 성능을 좌우합니다.

**Q. 연구용 프로토타입과 실제 서비스 소프트웨어의 차이는?**

 세 가지 관점에서 다릅니다.
1. **평가지표**: 연구는 정확도 SOTA가 목표지만, 서비스는 추론 속도·처리량·자원 효율도 핵심
2. **예외처리와 신뢰성**: 서비스는 예상치 못한 변수에 노출되므로 엣지 케이스 대응과 가드레일이 필수
3. **유지보수 라이프사이클**: 서비스 코드는 변하는 환경에 대응하기 위해 지속적 모니터링과 CI/CD 파이프라인이 필요

### 5-3. 프로젝트 기반 심화 질문

**Q. Adele Ring을 임베딩에 쓴다는 아이디어를 비전공자에게 30초 안에 설명해보세요**

기존 AI는 숫자를 그냥 문자처럼 분리해서 처리하기 때문에 3과 7을 더하면 10이 된다는 사실 자체를 배워야 합니다. 저는 수학의 Adele Ring이라는 구조를 활용해, AI가 숫자의 덧셈·곱셈 규칙을 처음부터 알고 시작하도록 임베딩 방식을 설계했습니다.

**Q. 기존 토큰화(BPE 등) 대비 AOE가 유리한 구체적 이유는?**

BPE는 숫자를 문자열로 분절하기 때문에 '123'이 '1', '23' 또는 '12', '3'으로 쪼개지며 대수적 의미가 소실됩니다. AOE는 숫자의 위치 정보(자릿수)와 p-adic 구조를 통해 수치 간의 대수적 관계를 임베딩 단계에서 보존합니다.

**Q. Training-free라고 했는데, downstream task fine-tuning 시 어떻게 통합하나요?**

**Q. p-adic을 몇 개 쓸지(어떤 소수 p 선택) 결정 기준은?**

표현하려는 수치 범위와 연산의 정밀도 요구사항에 따라 결정합니다. 소수 p의 선택은 해당 p-adic 표현이 커버하는 수 체계의 다양성과 계산 비용의 트레이드오프로 결정하며, 실험적으로 최적 집합을 탐색합니다.

**Q. KOSMOS-2 + Flan-T5 two-stage를 선택한 이유 (end-to-end 대신)?**

End-to-end 학습은 3B 파라미터 제약 안에서 시각 이해와 언어 생성을 동시에 최적화하기 어렵습니다. 두 단계로 분리해 KOSMOS-2는 공간 정보 추출에 집중하고, Flan-T5는 언어 생성에 집중하도록 각 모듈의 강점을 살릴 수 있었습니다.

**Q. QLoRA 적용 시 rank, alpha 하이퍼파라미터는 어떻게 결정했나요?**

메모리 예산과 파라미터 효율성 간의 균형을 기준으로, 낮은 rank(8~16)부터 시작해 검증 성능을 모니터링하며 탐색했습니다. alpha는 통상 rank의 2배 수준에서 시작하고, 학습 안정성을 보며 조정했습니다.

**Q. BLEU/METEOR/ROUGE의 한계 — 대안 척도는?**

이 지표들은 표면적 문자열 유사도를 측정하므로 의미적 일관성을 반영하지 못합니다. 대안으로 BERTScore(의미적 유사도), FActScore(사실 단위 검증), 또는 LLM-as-Judge 방식의 자동 평가 파이프라인이 환각 탐지에 더 적합하다고 생각합니다.

## 6. 압박 질문 대응

**Q. 연구실 경험으로 AI센터 업무를 할 수 있다고 생각합니까?**

연구실이 실제 FAB의 24시간 가동 환경을 완벽히 대변할 수 없다는 점은 잘 알고 있습니다. 하지만 연구실에서 쌓은 것은 단순 이론이 아니라, 현실 제약을 뚫어내는 치열한 가설 검증의 훈련이었습니다. 그 습관을 삼성의 생산성 혁신에 즉시 투입하겠습니다.

**Q. 더 뛰어난 지원자가 많은데 왜 뽑아야 합니까?**

저보다 코딩을 잘하거나 논문을 많이 쓴 분도 있을 것입니다. 하지만 AI가 숫자를 왜 못 다루는지 수학적으로 분해하고, 새로운 표현 방법을 직접 설계한 경험은 저만의 강점입니다. DS AI센터가 다루는 나노 단위 공정 데이터는 기존 AI로는 아키텍처 단에서부터 틀릴 수 있는 도메인입니다. 제 연구 스택은 그 문제와 가장 맞닿아 있습니다.

**Q. AI를 냅두고 왜 지원자를 뽑아야 합니까?**

범용 AI는 고신뢰성 파이프라인을 직접 구축하지 못합니다. 상용 LLM API만으로는 추론 속도, 전력 효율, 연산 정밀도를 세밀하게 제어할 수 없어 현장에서 오히려 거대한 오버헤드가 될 수 있습니다. 저는 반도체 도메인을 이해하고, 삼성전자의 인프라와 공정 제약에 맞춤형으로 최적화된 파이프라인을 밑바닥부터 설계할 수 있습니다.

**Q. 반도체 지식이 부족하면 살아남기 어렵지 않겠습니까?**

반도체 지식이 현업 전문가님들에 비해 부족한 것은 사실입니다. 하지만 낯선 분야를 빠르게 체득하는 노하우가 있고, 입사 후 사내 인프라와 현업 부서와의 소통을 통해 도메인 지식을 누구보다 빠르게 흡수하겠습니다. 

**Q. AI 분야는 변화가 매우 빠릅니다. 따라가지 못하면?**

변화 속도보다 새로운 기술이 실질적인 가치를 줄 수 있는지 선별하는 능력이 더 중요하다고 생각합니다. AI센터 내 기술 공유 문화를 적극 활용하고, 제가 가진 최신 정보를 동료들과 나누며 조직 전체의 기술력 유지에 기여하겠습니다.

**Q. 모델 성능이 기대에 못 미치면 어떤 책임을 질 수 있나요?**

모델 설계자로서 전적으로 제 책임입니다. 개발에서 끝내는 것이 아니라 현장에서 실제 가치를 만들어낼 때까지가 책임의 연장선이라고 생각합니다. 데이터 품질 문제인지, 분포 차이인지를 기술적으로 끝까지 추적하고 개선하겠습니다.

## 8. 면접 전략 핵심 원칙

1. **자소서를 완전히 자기 것으로 소화하라** — 자소서의 모든 내용이 면접 질문의 출발점이 됨
2. **기본기 + 논리적 사고를 보여라** — PT면접은 완성도보다 "이 사람이 기본기를 갖추고 논리적으로 사고하는가"를 봄
3. **스토리의 차별성이 합격을 만든다** — 스펙이 아닌 자기 경험을 직무와 연결하는 고유한 스토리가 중요
4. **반도체·AI 최신 이슈를 본인 직무 관점으로 연결하라** — HBM·GAA·EUV·AI반도체·온디바이스AI 등을 내 직무에서 어떤 의미인지 말할 수 있어야 함
5. **프로젝트 경험은 STAR 구조 + 수치화** — 상황(Situation)→과제(Task)→행동(Action)→결과(Result), 결과는 반드시 수치로 표현
6. **꼬리질문 대비가 합격을 가른다** — "왜 그렇게 생각하는가", "다른 방법은 없는가", "한계는 무엇인가"에 대한 깊이 있는 답변 준비
7. **Retention 관련 질문에는 반드시 긍정적으로** — 부서 배치, 스트레스, 이직 관련 질문은 조직 유지 가능성을 보는 것
