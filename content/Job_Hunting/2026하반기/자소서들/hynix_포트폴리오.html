SK하이닉스 AI해커톤 Portfolio Core Project 01 — <NUM> Token 기반 LLM 수치 임베딩 (진행중)
PROJECT 01 · IN PROGRESS
<NUM> Token 기반 LLM 수치 임베딩
FoNE·BitTokens류의 <NUM> 토큰 아키텍처에서, 수치 인코딩 모듈을 training-free AOE로 교체해 파라미터 증가 없이 LLM의 수치 추론 정확도·효율을 높이는 후속 연구
2026.04 – 현재  ·  GPT-2·LLaMA2 대상 파이프라인 설계 및 사전학습 실험 진행중
배경 — <NUM> 토큰 기반 수치 표현
기존 LLM은 숫자를 BPE로 분할해 표현하기 때문에, 자릿수·연산 정보가 토큰 경계에서 깨지는 문제가 있음

FoNE, BitTokens 등 최근 연구는 숫자를 하나의 <NUM> 토큰으로 치환하고, 그 임베딩을 규칙 기반 함수로 직접 계산해 주입·복원하는 구조를 제안
<NUM> 임베딩 방식 비교
구조수치 인코딩 방식
FoNEFourier 주기 특징
BitTokens이진수 비트열
OursAOE (대수구조 보존 임베딩)
핵심 아이디어
  • <NUM> 토큰 위치에서만, 일반 임베딩 테이블 대신 AOE 인코더가 계산한 벡터를 사용
  • 그 외 모든 텍스트 토큰은 기존 임베딩 테이블을 그대로 사용 — 모델 구조 변경 지점을 <NUM> 하나로 최소화
  • 출력 시엔 별도 Number Decode Head로 예측값 복원 (FoNE·BitTokens와 동일한 인터페이스, 인코더만 AOE로 교체)
<NUM> 토큰 결합 구조도
텍스트는 기존 임베딩 테이블을, 숫자는 학습 파라미터 없는 AOE 인코더를 거쳐 합쳐진 뒤 Transformer에 입력되고, 출력에서도 다음 토큰 예측과 숫자 예측이 갈라지는 구조
연구 목표 및 기대 효과 — AOE는 추가 학습 파라미터가 없는 training-free 인코더이므로, 모델 크기를 늘리지 않고도 ① 수치 인식의 근본적 개선, ② 수치 추론 정확도·학습 효율 증가, ③ 다자릿수 숫자를 단일 토큰으로 압축한 토큰 효율 증가를 함께 달성하는 것이 목표

SK하이닉스 AI해커톤 Portfolio Core Project 02 — Adelic Operation-preserved Embeddings
PROJECT 02 · RESEARCH
Adelic Operation-preserved Embeddings (AOE)
대수학적 구조를 유지하는 공간으로 숫자를 임베딩하여, 모델의 수치 이해 및 연산 성능을 최적화
NeurIPS 2025 Workshop MATH-AI  ·  Poster 2025.12.06  ·  "Numbers Already Carry Their Own Embeddings"
Motivation — 최신 LLM도 "5.9 = x + 5.11"처럼 간단한 산수를 종종 틀림. 숫자를 임의의 벡터로 다루는 기존 표현 방식 자체의 구조적 한계에서 기인한다고 보고 출발
Adele Ring 이란?
어떤 소수 p에 대한 p진수(ℚₚ)와 p진 정수(ℤₚ)가 있을 때, Adele ring 𝔸ℚ는 다음과 같이 정의됨:
𝔸ℚ  :=  ℝ  ×  ∏p (ℚₚ, ℤₚ)
핵심 성질
Element-wise Additive :  A(q₁+q₂) = A(q₁) ⊕ A(q₂)
Element-wise Multiplicative :  A(q₁×q₂) = A(q₁) ⊗ A(q₂)
예시
7/5  →  (1.4,  …11011₂,  …01212₃,  1.2₅,  …54130₇,  …)

확장 연구 — PFE (조화해석학 기반)
AOE가 수치 크기·패턴 보존에 집중했다면, PFE(Prime Fourier Embeddings)는 Pontryagin 쌍대성에 기반해 정수를 소수-인덱스 (cos, sin) 쌍으로 인코딩합니다. 각 소수 채널을 하나씩 가려보는 ablation 실험으로, 모델이 실제로 연관 소수 채널을 사용해 답을 낸다는 것을 확인했습니다.

SK하이닉스 AI해커톤 Portfolio Core Project 06 — Finance Jarvis
PROJECT 06 · PERSONAL PROJECT
Finance Jarvis
Claude Code와 협업해 설계부터 실제 계좌 검증까지 진행한 KIS(한국투자증권) API 기반 자동매매 엔진
2026.09.19 – 09.22 (4일)  ·  개인 사이드 프로젝트  ·  KIS OpenAPI 기반
배경 & 설계 방향
기존에 만들어 둔 개인 종목 스캐너(기술적 시그널 + 뉴스 감성분석)를, 실제 주문이 나가는 자동매매 엔진으로 확장한 프로젝트입니다.

실거래 전환이 전제된 시스템이라 기능을 넓히기 전에 "장애에 견고한 설계"를 먼저 세웠습니다. 특히 매매 판단을 숫자로 계산되는 판단과 LLM이 맥락을 읽고 내리는 판단으로 처음부터 분리해, 후자는 사람 승인 없이는 매매에 반영되지 않도록 설계했습니다.
Claude Code 협업 방식
  • Explore 에이전트로 API 문서·예제 코드를 먼저 조사
  • Plan 에이전트에게 크래시 복구, 중복주문 방지, DB 스키마 설계를 교차검토받은 뒤 구현
  • 최소 안전 코어부터 구현하고, 리스크 낮은 기능부터 단계적으로 확장
  • 실제 모의투자 계좌로 매 단계 라이브 검증, 발견된 버그는 즉시 원인을 추적해 수정
판단 아키텍처 — 계산 기반 판단과 Gemini 기반 semantic 판단의 분리
결정론적 계산 Gemini 기반 semantic 판단 (승인 게이트 통과 필요)
검증은 유닛테스트로 끝내지 않고, 단계마다 실제 모의투자 계좌로 시세 조회·주문·체결을 직접 호출해 확인했습니다. 이 과정에서 계산 레이어가 쓰던 기술적 지표 라이브러리 하나가 수식 오류로 값을 수백 배까지 부풀려 계산하고 있다는 것을 발견해, 수동 계산과 대조하여 원인을 찾아 고쳤습니다.
나흘 만에 20개가 넘는 모듈, 커밋 8개로 자동매매 엔진을 완성해 실제 정규장 시간에 모의투자 계좌로 라이브 검증까지 마쳤습니다.
모의투자 계좌 기준 검증이며, 실거래 전환에는 별도 이중 확인이 필요하도록 설계했습니다. 해외주식은 시세·잔고 조회까지만 검증했고 실주문 체결 전체 사이클은 아직 미검증입니다.
