PROJECT 01 · RESEARCH
Adelic Operation-preserved Embeddings (AOE)
대수학적 구조를 유지하는 공간으로 숫자를 임베딩하여, 모델의 수치 이해 및 연산 성능을 최적화
NeurIPS 2025 Workshop MATH-AI  ·  Poster 2025.12.06  ·  “Numbers Already Carry Their Own Embeddings”
Motivation — 최신 LLM도 “5.9 = x + 5.11”처럼 간단한 산수를 종종 틀림. 숫자를 임의의 벡터로 다루는 기존 표현 방식 자체의 구조적 한계에서 기인한다고 보고 출발
Adele Ring 이란?
어떤 소수 p에 대한 p진수(ℚₚ)와 p진 정수(ℤₚ)가 있을 때, Adele ring 𝔸ℚ는 다음과 같이 정의됨:
𝔸ℚ  :=  ℝ  ×  ∏p (ℚₚ, ℤₚ)
핵심 성질
Element-wise Additive :  A(q₁+q₂) = A(q₁) ⊕ A(q₂)
Element-wise Multiplicative :  A(q₁×q₂) = A(q₁) ⊗ A(q₂)
예시
7/5  →  (1.4,  …11011₂,  …01212₃,  1.2₅,  …54130₇,  …)
임베딩 파이프라인
숫자를 소수별 p진 전개 벡터로 분해해 텐서 A(q)로 결합한 뒤, 평탄화·2D 위치 인코딩을 더해 시퀀스로 변환하는 AOE 임베딩 과정
성능 검증 모델 구조
Baseline: Trainable nn.Embedding + 1D PE
Ours: AOE + 2D PE

PROJECT 02 · RESEARCH
Prime Fourier Embeddings (PFE)
조화해석학으로 Adele 환의 Fourier 변환을 활용, 모델이 소수(prime) 정보를 보다 용이하게 사용하도록 설계
ICML 2026 Workshop AI4MATH  ·  Poster 2026.07.11  ·  “Prime Fourier Embeddings: A Principled Basis for Modular Arithmetic”
PFE 란?
정수 a를 소수 p, 자릿수 깊이 d 까지 독립된 (cos, sin) 쌍으로 인코딩:
PFEp,d(a)  =  [ cos(2πa / pd+1),  sin(2πa / pd+1) ]
핵심 성질
0~p−1 사이의 정수를 사용했던 AOE와 달리, −1~1 사이의 연속값으로 각 p진수를 인코딩
덧셈을 각도의 회전 덧셈과 동치로 볼 수 있음
예시
1247  ↦  ([0.396, 0.918], [0.988, −0.150], [−0.659, −0.752], …)
소수별 (cos, sin) 인코딩 채널
각 소수 p, 자릿수 깊이 d 별로 독립된 (cos, sin) 채널을 두어 하나의 텐서로 결합
검증용 모델 구조
“a + b mod q” modulo 연산 태스크로 성능 검증

배 수 현 · Portfolio Core Project 03 — <NUM> Token 기반 LLM 수치 임베딩 (진행중)
PROJECT 03 · IN PROGRESS
<NUM> Token 기반 LLM 수치 임베딩
FoNE·BitTokens류의 <NUM> 토큰 아키텍처에서, 수치 인코딩 모듈을 training-free AOE로 교체해 파라미터 증가 없이 LLM의 수치 추론 정확도·효율을 높이는 후속 연구
고려대 수리인공지능 연구실  ·  2026.04 – 현재  ·  GPT-2·LLaMA2 대상 파이프라인 설계 및 사전학습 실험 진행중
배경 — <NUM> 토큰 기반 수치 표현
기존 LLM은 숫자를 BPE로 분할해 표현하기 때문에, 자릿수·연산 정보가 토큰 경계에서 깨지는 문제가 있음

FoNE, BitTokens 등 최근 연구는 숫자를 하나의 <NUM> 토큰으로 치환하고, 그 임베딩을 규칙 기반 함수로 직접 계산해 주입·복원하는 구조를 제안
<NUM> 임베딩 방식 비교
구조수치 인코딩 방식
FoNEFourier 주기 특징
BitTokens이진수 비트열
OursAOE (대수구조 보존 임베딩)
핵심 아이디어
  • <NUM> 토큰 위치에서만, 일반 임베딩 테이블 대신 AOE 인코더가 계산한 벡터를 사용
  • 그 외 모든 텍스트 토큰은 기존 임베딩 테이블을 그대로 사용 — 모델 구조 변경 지점을 <NUM> 하나로 최소화
  • 출력 시엔 별도 Number Decode Head로 예측값 복원 (FoNE·BitTokens와 동일한 인터페이스, 인코더만 AOE로 교체)
<NUM> 토큰 결합 구조도
<NUM> 위치에서만 AOE 인코더 임베딩을 사용하고, 다른 토큰·트랜스포머 구조는 그대로 유지 — 변경 지점을 최소화한 결합 구조
연구 목표 및 기대 효과 — AOE는 추가 학습 파라미터가 없는 training-free 인코더이므로, 모델 크기를 늘리지 않고도 ① 수치 인식의 근본적 개선, ② 수치 추론 정확도·학습 효율 증가, ③ 다자릿수 숫자를 단일 토큰으로 압축한 토큰 효율 증가를 함께 달성하는 것이 목표
