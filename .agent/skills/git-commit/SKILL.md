# Git 자동 커밋 워크플로우 (git-commit)

사용자가 "커밋", "커밋 남겨", "/commit" 등을 요청했을 때 불필요한 질의응답 없이 신속하게 변경 사항을 파악하고 커밋을 완료하는 가이드입니다.

## 실행 절차

1. **변경 사항 확인**:
   - `git status -s` 명령어를 실행하여 변경(Modified), 추가(Untracked), 삭제(Deleted)된 파일 목록을 확인합니다.
   - 필요 시 `git diff --stat`로 변경 규모를 확인합니다.

2. **커밋 메시지 생성 규칙**:
   - Conventional Commits 형식 준수: `<type>(<scope>): <설명>`
     - `docs`: 자소서, 이력서, 포트폴리오, logs 등 문서 수정/추가
     - `feat`: 신규 기능, 스크립트, 에이전트 스킬 추가
     - `fix`: 오타, 수치 오류, 링크 불일치 등 사실관계 수정
     - `refactor`: 가독성 개선, 파일 구조 분리, 텍스트 재배치
     - `chore`: 빌드, 설정, 사소한 정리
   - 한글로 간결하고 명확하게 변경의 핵심 의도를 1줄로 작성합니다.

3. **스테이징 및 커밋 실행**:
   - PowerShell 환경 특성상 `&&` 대신 세미콜론(`;`)을 사용합니다.
   - 예시:
     ```powershell
     git add "경로1" "경로2"; git commit -m "docs(scope): 커밋 메시지 내용"
     ```
   - 특정 임시 파일(임시 로그, 미완성 scratch 파일 등)이 명백히 제외되어야 하는 경우가 아니라면, 작업한 관련 파일들을 정확히 지정하여 스테이징합니다.

4. **결과 보고**:
   - 생성된 커밋 해시(Short Hash)와 커밋 메시지, 변경된 파일 목록을 간결하게 사용자에게 안내합니다.
