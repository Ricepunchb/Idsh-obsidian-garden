# 자소서 작성/재작성 스킬 (Antigravity)

이 볼트는 회사별 자소서를 `content/Job_Hunting/2026하반기/자소서들/{회사명} 자소서.md`에 저장하고,
재사용 가능한 경험은 별도 포트폴리오 문서에서 관리한다. 매번 새로 쓰지 말고 아래 순서를 따른다.

## 0. 항상 먼저 읽는 세 문서

1. `content/Job_Hunting/자소서_가이드라인.md` — 톤앤매너·구조·직무연관성·디테일 깊이 규칙. 모든 문장이 이 규칙을 통과해야 한다.
2. `content/Job_Hunting/내 포트폴리오 아이템 정리.md` — 재사용 가능한 경험/연구/프로젝트 단위 정리. 문항에 쓸 소재는 여기서 고른다. 특히 각 아이템의:
   - "본인 기여 범위" (팀 성과를 단독 성과처럼 과장하지 않기)
   - "진행중 vs 완료" 구분 (완료된 논문 성과와 현재진행중 후속 연구를 섞어 인과관계를 조작하지 않기)
   - "NDA/공개 수위" 주의사항
   을 반드시 확인하고 위반하지 않는다.
3. `content/Job_Hunting/2026하반기/logs/{회사명}.md` — 해당 회사 JD 원문, 서류/코테 일정. JD의 "수행업무"·"필요역량"·"우대사항"을 스펙 시트로 취급해 커버리지 표를 머릿속으로(또는 실제로) 만든다.

기존 자소서 파일이 이미 있으면 그것도 읽어서, 어떤 문항이 이미 검증된 소재(과거 서류 합격 이력)를 쓰고 있는지 파악한다. 검증된 소재는 함부로 갈아엎지 말고, 사용자가 명시적으로 "이건 바꾸고 싶다"고 한 문항만 재구성한다.

## 1. 문항별 소재 배정 및 스토리라인 (One Theme, One Narrative)

- **하나의 관통하는 스토리라인 (필수)**: 화려한 스펙 나열은 평가관 눈에 다 고만고만해 보인다. 문서 전체가 지원자의 **단 하나의 핵심 정체성(코어 테제)**을 입체적으로 증명하는 단일 서사로 맞물려야 한다. (동기 → 역량 → 도전/집요함 → 협업 인터페이스 → 윤리/안전 통제).
- **지원동기의 철칙: 첫 문단 두괄식 "Why {회사명}?" (필수)**:
  - "이 역량 가지고 다른 곳을 가도 되는데, **왜 하필 여기인가?**"를 첫 문단에 즉시 답한다. 뒷문단으로 미루지 않는다.
  - `[일반 상용/타사 시장 대비] + [타깃 조직만의 고유한 사명/문제 정의/공적 위상] + [내 핵심 역량/연구 철학이 가장 절실하게 쓰일 곳이라는 필연적 합치 선언]`
- 문항 텍스트를 절 단위로 쪼개 요구사항 체크리스트를 만든다 (가이드라인 2-①).
- JD 키워드(예: "추론 모델 학습", "검증기 결합", "정렬 및 보상 신호", "평가 벤치마크", "실패 분석")를 포트폴리오 아이템과 매칭한다. 라벨 대 라벨 매칭이 아니라 "문제의 구조"로 연결한다 (가이드라인 3-③).
- 같은 경험을 문항마다 다르게 쓰는 건 괜찮지만, 이미 이 문서의 다른 문항이나 이 회사의 CV형 항목에서 쓴 경험은 가급적 피하거나 각도를 바꾼다(가이드라인 2-⑤). 사용할 수 있는 소재가 마땅치 않으면 사용자에게 방향을 제안하고 실제 경험을 물어본다 — 지어내지 않는다.
- 진행중인 연구를 쓸 때는 완료된 성과(논문 게재 등)와 진행중 작업(아직 미게재)을 한 문장 안에서도 명확히 분리해서 서술한다. "그 결과 게재되었다"처럼 진행중 작업을 완료 성과로 귀속시키는 인과 오류를 만들지 않는다.

## 2. 문장 작성 규칙 (인간적인 글, AI 티 완벽 박멸)

- **기업 채용팀의 AI 탐지 솔루션 대비 (4대 대표 AI 시그널 철저 배제)**:
  1. **지나친 쉼표(,) 남발 금지**: 사람은 쉼표를 자주 안 쓴다. 문맥으로 자연스럽게 이어질 수 있는 곳에 습관적으로 마디마디 찍힌 쉼표를 적극 제거한다.
  2. **가운뎃점(·) 사용 절대 금지**: 키보드에 없는 특수문자로 AI의 전형적인 시그니처다. 쉼표(,), 슬래시(/), 공백, 접속사('및', '와/과')로 쓴다. (문항 원문만 보존)
  3. **단어 뒤 불필요한 영단어 괄호 병기 금지**: `파인튜닝(fine-tuning)`, `환각(hallucination)`처럼 누구나 아는 기술 용어에 원어 괄호를 붙이지 않는다. 한국어로 쓰거나 고유 약어(LLM, QLoRA) 자체로만 쓴다.
  4. **'앞 볼드체 + 뒤 콜론(:) 요약 설명' 문법 금지**: `**문제 정의**: ~` 처럼 문장을 토막 내는 방식은 대표적인 프롬프트 생성 냄새다. 본문은 줄글 에세이 형태의 호흡으로 서술한다.
- **기계적 병렬 나열 금지**: "첫째, ~ 둘째, ~ 셋째, ~ 넷째, ~", "첫 번째 문제는, 두 번째 문제는" 식의 로봇 같은 나열을 절대 피한다. 맥락과 흐름을 살려 이야기식으로 자연스럽게 전환한다.
- **인위적 1:1 매핑 금지**: "앞서 소개한 세 연구는 세 가지 목표와 같습니다" 식의 억지 정렬 금지.
- **실패와 난관의 "생생한 호흡"**: 매끄러운 성공 요약 대신, 현장의 날것의 고민, 가설과 현실의 괴리, 직접 손으로 수습한 구체적 시행착오가 살아있어야 한다.
- **문장 리듬과 호흡**: 단문과 복문을 조화롭게 섞어 사람이 호흡하며 쓴 글처럼 만든다. 반복되는 종결 어미("-했습니다. -했습니다. -했습니다")를 깨뜨린다.
- **격식체 통일**: "-습니다"체로 통일, 구어·축약("나눠"→"나누어", "겪어봤"→"겪어보았") 제거.
- **강한 동사, 완화 표현 금지**: "~하려고 노력했습니다", "~인 것으로 생각됩니다" 대신 능동적인 직설 화법 사용.
- **확신의 크기 = 증거의 크기**: 프로젝트 1건을 분야 전체로 확장하지 않기.
- **인용 부호**: 큰따옴표(`"..."`)만 사용. 작은따옴표(`'...'`) 금지.
- **재등장 단어 제거**: 한 문단 내에 같은 단어나 개념이 중복 등장하지 않도록 정제.
- **시선론(Eye-tracking)과 압축적 가독성 (Skimmability)**:
  - 평가관은 문장을 정독하지 않고 F자로 스캔한다. 문단 간 연결을 매끄럽게 늘이기보다, **훑어봤을 때 말하고자 하는 바가 3초 안에 꽂히는 압축성**을 최우선한다.
  - **소제목/두괄식 선언**: 문단 서두에 무엇을 말할 것인지를 소제목이나 두괄식 테제로 먼저 선언한다.
  - **정량적 골격 서술**: "무엇을 하여 어떤 결과를 냈다"는 행동-성과 중심의 명확한 뼈대 문장을 세운다.
  - **숫자와 영어의 시각적 앵커링**: 아라비아 숫자(`66%→92%`, `75%`, `2배`)와 영문 고유명사(`Adele Ring`, `Lean4`, `QLoRA`)는 시선이 가장 먼저 머무는 랜드마크이므로, 대충 훑어봐도 성과와 기술 스택이 드러나도록 전략적으로 배치한다.
- **사실관계·수치·고유명사 불변 원칙**: 문체는 사람답게 유려하게 다듬되, 실험 조건, 정확도 수치, 저자 서열, 진행 단계 등의 사실은 1%도 왜곡하지 않는다.

수정 후 반드시 PowerShell로 공백 포함/제외 실측을 수행한다:

```powershell
$path = "content/Job_Hunting/2026하반기/자소서들/{회사명} 자소서.md"
$content = Get-Content -Path $path -Raw -Encoding UTF8

```

## 4. 마무리 체크리스트

1. **지원동기 첫 문단에 "Why {회사명}?" 두괄식이 확실히 박혔는가?** (시장 대비 + 조직 위상 + 내 철학 합치)
2. **전체 문항이 하나의 관통하는 스토리라인(One Narrative)으로 유기적으로 엮였는가?** (파편화된 스펙 나열 탈피)
3. **시선론/스캐너빌리티가 확보되었는가?** (소제목/두괄식, 숫자와 영문 키워드로 3초 안에 핵심 스캔 가능 여부)
4. 질문의 각 절이 빠짐없이 답변되었는가?
5. JD 핵심 키워드가 자연스럽게 스며들었는가?
6. **AI 냄새(첫째/둘째/셋째, 인위적 1:1 대칭, 상투적 어구, 가운뎃점 남발)가 완전히 빠졌는가?**
7. 사실관계, 진행/완료 구분, 기여 범위가 포트폴리오 원문과 정확히 일치하는가?
